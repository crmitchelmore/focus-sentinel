# Every TCC-protected API family this application's code could touch, and the proof for each
# that it neither asks for the grant nor holds one (e07 invariant **I-3**, F-128).
#
# WHY THIS FILE EXISTS. Five plans cite "this app asks for no TCC permission of any kind" as a
# ruling, and until this round the proof of it was scattered: SC-1 banned one CoreGraphics key,
# R-33 banned eight source-level request calls, R-96s banned five notification selectors in the
# Release Mach-O, and `check-notification-denied.sh` read one counter out of the running app.
# Four readings about three families. Nothing said what the *other* seven families were, and a
# family nobody named is a family nobody checked. This table is the vocabulary; `check-grants.sh`
# is the single fold over it, and it reads both the artefact and the running application.
#
# ROW SHAPE — six columns, separated by ` · `:
#
#     <family> · <banned> · <controls> · <capability> · <allowed states> · <note>
#
# AMENDED 2026-10-15 (issue #24, owner's ruling). The accessibility family's two READ selectors
# — `AXUIElementCreateApplication` and `AXUIElementCopyAttributeValue` — left its `banned` column
# and are confined to one file by `Config/grant-use-sites.txt`, which `check-grants.sh` folds over
# beside the request registry. The selectors that write to, act on, observe or bulk-read another
# application stay banned. Screen Recording is unchanged: still asked for only on opt-in, still
# read by nothing.
#
# AMENDED 2026-09-09 (focus-exdi.4, owner's ruling). Two families — accessibility and
# screenRecording — may now be ASKED for, where the person switched the ask on in Settings. Their
# `banned` columns therefore name the *use* selectors only, which are still banned because nothing
# in this build reads what either grant unlocks; the request selectors moved to
# `Config/grant-request-sites.txt`, which confines them to one named file and which
# `check-grants.sh` folds over beside this table. The doctrine is now conditional and is stated in
# `GrantOptIn`: the app asks for nothing unless the person switched that ask on.
#
#   family          one of the ten names below. The vocabulary is closed: `check-grants.sh`
#                   carries the same ten and fails if the table names a different set, so a row
#                   cannot be deleted, renamed or quietly merged into its neighbour.
#   banned          comma-separated selectors, class names and symbols whose presence in the
#                   shipped Mach-O would mean the app can ASK for that grant. Matched against the
#                   union of `nm -u` and `strings -a`, because a Swift call to a C function shows
#                   up as an undefined symbol and an Objective-C selector shows up as a string.
#   controls        symbols that must be PRESENT, because they are the grant-free reading the app
#                   really does make of that family. Without one, "no request selector" is a
#                   statement about a binary that has no relationship with the family at all —
#                   which is the same green a build that dropped the framework would produce.
#                   NONE where the app touches the family in no way whatsoever; the fold then
#                   holds that family to the global symbol-universe floors instead.
#   capability      the `Capability` case the app publishes for this family, or NONE.
#   allowed states  the `CapabilityState` values the running app may report for it. `available`
#                   appears in exactly one row, and that row's note has to say what grant-free
#                   mechanism produces it.
#   note            why the reading is grant-free, in one sentence a person reads.
#
# WHERE A FAMILY'S BAN LIVES SOMEWHERE STRONGER. `screenRecording`'s worst symbol is the
# window-list key that needs the grant, and SC-1 already bans it by name across the whole
# repository and in seven build products one at a time. Repeating it here would weaken nothing
# and would make SC-1 fail on this file, so the row's note points at it instead.
#
# THE ONE `available`. `microphoneActivity` reads `available` on a Mac with a microphone, and it
# is not a grant: `kAudioDevicePropertyDeviceIsRunningSomewhere` is a property of a CoreAudio
# device object, readable by any process, and it says only that *somebody* on this Mac is
# recording. Capturing audio would need `AVCaptureDevice`, which is in this row's banned column.

accessibility · AXUIElementSetAttributeValue,AXObserverCreate,AXUIElementCopyAttributeValues,AXUIElementPerformAction · _AXIsProcessTrusted · accessibilityWindowContext · notRequested,denied,restricted,unavailable,available · The app reads whether it is trusted, and asks to become trusted only where the person switched that ask on in Settings (focus-exdi.4): available here means the person said yes and macOS agreed, never that the app took it. Since issue #24 it also reads, on device, the frontmost application's selected row or main heading, then its window title, within a bounded walk, and keeps only a short selected-item name. Browser content uses the focused document or web-area URL, reduced to an HTTP(S) host and path without credentials, query or fragment; exports remove the path. Only where someone configured the opt-in remote judge (RemoteJudgeConfiguration, off by default and never in a lane), it also reads the cleared frontmost window's title, file, web address, focused element and bounded text through the same three selectors, and DecisionOneJudge sends that once, unstored. Those read selectors are confined to one file by Config/grant-use-sites.txt, and every selector that would write, act, observe or bulk-read stays banned above.
screenRecording · SCShareableContent,CGWindowListCreateImage,CGDisplayStream,SCStreamConfiguration,CGDisplayCreateImage · _CGWindowListCopyWindowInfo · screenCapture · notRequested,denied,restricted,unavailable,available · The window list gives geometry, layer and owner name without a grant, and the one key in it that would need one is banned by SC-1 repository-wide and in seven build products. Pixel capture is asked for only where the person switched that ask on (focus-exdi.4) and is still read by nothing, so every capture selector above stays banned.
automation · NSAppleScript,NSAppleEventDescriptor,AEDeterminePermissionToAutomateTarget,AESendMessage,OSAScript · NONE · NONE · NONE · The app drives no other application, so there is nothing to be automated and no Apple Event to send.
notifications · requestAuthorizationWithOptions,addNotificationRequest,setNotificationCategories,UNNotificationRequest,UNMutableNotificationContent · currentNotificationCenter,getNotificationSettingsWithCompletionHandler · notifications · notRequested,denied,restricted,unavailable · U-2 took the notification rung off the ladder; what is left is reading the settings the person already chose, which prompts nobody.
camera · AVCaptureDevice,AVCaptureSession,requestAccessForMediaType · _CMIOObjectGetPropertyData · cameraActivity · notRequested,denied,restricted,unavailable · CMIO property reads say whether a camera is running; opening one would need the grant and the app never opens one.
microphone · AVAudioApplication,AVAudioSession,requestRecordPermission,AVCaptureDeviceInput · _AudioObjectGetPropertyData · microphoneActivity · available,notRequested,denied,restricted,unavailable · kAudioDevicePropertyDeviceIsRunningSomewhere is a device property any process may read; it needs no grant and yields no audio.
inputMonitoring · IOHIDRequestAccess,CGRequestListenEventAccess,CGRequestPostEventAccess,CGEventTapCreate,IOHIDManagerCreate · NONE · NONE · NONE · Idle time comes from CGEventSource's seconds-since-last-event, which is a number and not a keystroke; the app taps no events.
location · CLLocationManager,requestWhenInUseAuthorization,requestAlwaysAuthorization,startUpdatingLocation · NONE · NONE · NONE · Nothing this app decides depends on where the Mac is.
contacts · CNContactStore,requestAccessForEntityType,CNAuthorizationStatus · NONE · NONE · NONE · The app knows about applications and priorities, never about people.
calendar · requestAccessToEntityType,requestWriteOnlyAccessToEvents,requestFullAccessToReminders,saveEvent:span,removeEvent:span · authorizationStatusForEntityType · calendarEvents · notRequested,denied,restricted,unavailable,available · The app reads its calendar authorisation without asking, and asks for full access to events only where the person switched that ask on in Settings (focus-cal): available here means the person said yes and macOS agreed. What it then reads is when events start and end, never their titles or attendees, and it writes nothing — so every write selector and every older or wider ask above stays banned.
